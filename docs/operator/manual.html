For a Splashery session: American English in the app and its README
Switch Splashery to American English spelling, in the app and its documentation together.

Why: I am American and write American English. The README and the app's own text currently use British spellings (colour, colours, maths, synthesised, recolour, haemoglobin and others), and the README quotes strings the app displays, so the two must change together.

Scope: every string a person can read (the panel, status lines, toy names and notes, the manual, the README, docs, comments) and the identifiers behind them where a rename is safe. Leave alone: anything in vendor/, third-party names and credits as their authors wrote them, and saved-scene keys or URL parameters that existing links depend on. Where a key in a shared link or the scene schema is spelled the British way, keep reading the old key and say so in your report instead of renaming it.

A checker exists in my portfolio repo: `gh api repos/ryanjosephkamp/portfolio/contents/tools/us-spelling.mjs -H "Accept: application/vnd.github.raw"`. Save it to a scratch file and run it with a path to list hits, or with `--fix` to apply them. It renames identifiers too, the same way in every file it is given, so read the diff and run the full test suite afterward.

Done when: the checker prints nothing for the app's own files, the tests pass, a shared link made before the change still opens, and a pull request is open. Reply with the count fixed, anything you deliberately kept, and why.

Rules

Three, and each has a way to check it. They sit at the top of CLAUDE.md, which every session on this repo loads by itself.

  1. American English.US spelling and US dates in pages, code, comments, commit messages and pull requests. Checked by node tools/us-spelling.mjs <path>, which must print nothing before a session ships. Also a standing instruction for every project on this machine.
  2. Project-first.A page says what a project does and what a visitor can do with it. How it was made, AI assistance included, stays off the page. Workshop is the one exception.
  3. Claim-safe.Every factual sentence traces to docs/FACTS.md, a public README, or a live page. Interests are written as interests. Each session lists the lines that are invented voice.

The process itself, seven steps from gathering facts to shipping, is docs/PLAYBOOK.md.
